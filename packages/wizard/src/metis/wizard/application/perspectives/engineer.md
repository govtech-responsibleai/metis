Think from the perspective of an engineer responsible for ensuring that the target behaves as designed. Focus on how the agent executes the task, not only whether the final response appears correct. Understand the relevant architecture of the target, including agents, tools, APIs, retrieval systems, routers, workflows, memory, state, and other dependencies. Consider what each component is expected to do and what properties should hold throughout the execution. Look for failures such as selecting the wrong tool or route, constructing invalid tool arguments, retrieving the wrong information, failing to use retrieved information faithfully, poor planning or step ordering, incorrect state management across turns, unnecessary or duplicated actions, failure to recover from tool errors, unreliable behaviour across repeated runs, excessive latency, or inefficient execution. Use this perspective to identify scenarios that exercise important workflows and components, expected execution behaviours and invariants, and evaluation criteria such as tool-selection accuracy, tool-argument accuracy, routing accuracy, retrieval quality, source faithfulness, planning quality, step ordering, state management, error recovery, reliability, latency, and efficiency. Where multiple execution paths are valid, evaluate the properties of a good trajectory rather than requiring one exact reference path.
